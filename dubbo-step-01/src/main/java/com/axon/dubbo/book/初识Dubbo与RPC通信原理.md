## 第1章 初识Dubbo与RPC通信原理

### 1.1 Dubbo发展史和架构鸟瞰

#### 1.1.1 Dubbo发展简史

Dubbo 诞生于 2011 年，由阿里巴巴主导开发，是国内首屈一指的高性能 RPC 框架。在国内微服务架构的演进过程中，Dubbo 一直处于领导地位，尤其是在互联网、电商、金融等高并发行业场景广泛应用。
其关键发展阶段如下：

* **Dubbo 1.x**：起步于阿里巴巴内部，解决大规模 SOA 架构下的服务治理、性能与扩展性问题。
* **Dubbo 2.x**：完全开源，社区壮大，接口、协议、扩展机制全面升级，支持多种注册中心、多协议与序列化。
* **Dubbo 2.7.x**：全面支持 Spring Boot，升级 SPI、元数据中心、Triple 新协议，支持云原生生态。
* **Dubbo 3.x**：拥抱微服务、云原生与 Service Mesh，更强的多协议、异步流式与多语言能力。

#### 1.1.2 Dubbo 典型应用场景

* 大型网站的分布式服务拆分与治理
* 金融/电商平台的高并发后端接口调用
* 复杂企业服务集群的弹性扩展与容错治理

#### 1.1.3 Dubbo 架构鸟瞰

Dubbo采用**分层解耦**、**模块化扩展**的设计理念。其主要架构分为三层：

* **服务层（Service Layer）**：暴露与消费服务接口。
* **注册发现层（Registry Layer）**：负责服务的注册与发现。
* **远程通信层（Remoting Layer）**：实现底层通信协议与序列化。

其典型的分布式部署拓扑如下：

```
+---------------------+      +---------------------+      +---------------------+
|     服务消费者       | <--->|    注册中心         |<---->|    服务提供者       |
|  (Consumer)         |      |   (Registry)        |      |   (Provider)        |
+---------------------+      +---------------------+      +---------------------+
        |                                                         |
        |   远程过程调用（RPC）                                    |
        +---------------------------------------------------------+
```

### 1.2 Dubbo各核心模块职责和依赖关系

Dubbo的核心模块及其职责：

| 模块名           | 职责描述                          | 主要依赖关系            |
| ------------- | ----------------------------- | ----------------- |
| Protocol      | 通信协议抽象，定义RPC请求的传输与序列化过程       | Invoker、Exporter  |
| Invoker       | 执行服务调用，统一调用入口                 | Protocol、Cluster  |
| Exporter      | 暴露服务，将服务对象导出到指定端口             | Protocol、Invoker  |
| Registry      | 注册中心，管理服务注册/发现                | URL、Directory     |
| Directory     | 持有服务实例Invoker的目录，负责服务路由与动态刷新  | Invoker、Registry  |
| Cluster       | 集群容错与负载均衡                     | Directory、Invoker |
| Router        | 路由规则，决定服务选择策略                 | Directory         |
| Filter        | 调用链扩展点，实现自定义拦截器、限流、监控等        | Invoker           |
| Serialization | 对象的序列化/反序列化                   | Protocol          |
| Config        | 全局配置与参数透传                     | URL               |
| SPI扩展         | Dubbo的插件化与自适应机制，所有核心点都基于SPI实现 | 所有扩展点             |
| Monitor       | 服务调用统计与监控                     | Filter、Config     |

Dubbo整体设计采用“面向接口编程”，核心依赖关系清晰，各模块解耦且可以通过SPI动态替换。

### 1.3 RPC请求-响应基本模型

**RPC（Remote Procedure Call）远程过程调用**，是分布式系统中最基础的通信模式。Dubbo 通过对 RPC 进行高度抽象与扩展，支撑起了复杂的服务治理体系。

#### 1.3.1 基本流程

1. **服务暴露**
   服务提供者实现业务接口，通过Protocol/Exporter暴露本地服务为远程服务，并将服务地址注册到注册中心。

2. **服务发现**
   服务消费者从注册中心获取可用服务列表，并为远程服务生成本地代理对象（通过动态代理实现接口透明调用）。

3. **远程调用**
   消费者调用代理对象的方法时，代理将方法参数封装成RPC请求对象，通过网络传递到服务端。

4. **服务执行与响应**
   服务端收到请求后，反序列化请求对象，执行对应服务方法，将结果序列化后返回给消费者。

5. **结果返回**
   消费者收到响应数据，解包并还原为本地方法的返回值。

#### 1.3.2 Dubbo RPC请求-响应流程示意

```
Consumer
   |
   |---> [代理层] method()  
   |---> [序列化] 封装请求参数
   |---> [网络层] 发送请求到Provider
   |
Provider
   |
   |<--- [网络层] 接收请求
   |<--- [反序列化] 还原请求
   |<--- [反射调用] 执行真实方法
   |---> [序列化] 封装响应结果
   |---> [网络层] 发送回Consumer
```

#### 1.3.3 Dubbo通信协议与序列化

* 支持多协议（Dubbo、RMI、HTTP、Hessian、Triple等）
* 支持多种序列化方式（Java、Hessian2、FastJSON、Protobuf等）
* 协议层与序列化层完全解耦
